# Вёрстка сайта «Частные балы»

Цель — одностраничный сайт по макету v2 (десктоп 1440, планшет 834, телефон 390), готовый к заливке на хостинг.
**Готовый к деплою проект — папка `Частные балы сайт/site/`**: в ней лежит ровно то, что заливается на сервер, и ничего больше.
План, журнал, инструменты и сверки — здесь, в `Доработка/вёрстка/`.

## Решения пользователя (2026-10-02)

1. **Хостинг — российский с PHP** (Beget / Timeweb / REG.RU). Папка `site/` заливается целиком по FTP / SFTP, Apache + `.htaccess`.
2. **Куда уходят заявки — решить позже.** До этапа 6 форма — интерфейс с состояниями; обработчик `send.php` подключается на этапе 6.
3. **Аналитика — решить позже.** Место под счётчик и плашку cookie закладывается, подключение — на этапе 6 или 7.

## Стек

- **Чистые HTML, CSS и JS, без фреймворка и без сборки.** Одна страница `index.html` плюс `privacy.html` и `404.html`.
- CSS — несколько файлов по слоям (см. структуру). Фреймворков и препроцессоров нет. Нужны custom properties, `clamp()`,
  container-free медиазапросы по брейкпойнтам 600 / 1024.
- JS — ES-модули (`<script type="module">`) без бандлера. Без jQuery, GSAP и Lenis: скраба по скроллу в макете нет.
  Анимации входа — IntersectionObserver + Web Animations API / CSS-переходы.
- Прокрутка нативная, без «плавного скролла».
- Шрифты — **свои, без Google Fonts** (запросы к Google из РФ медленные и передают IP за рубеж). Unbounded (OFL, статичные срезы 400 и 700
  из variable — этап 2) и Old Standard TT Regular + Italic, сабсет латиница + кириллица, `woff2`, `font-display: swap`, preload двух основных файлов
  (Unbounded Bold, Old Standard Regular).
- Фото — AVIF + WebP + JPEG через `<picture>` и `srcset` под 1× / 2× / 3×. Кропы — отдельные файлы под каждую раскладку
  (`<source media>`): `site/img/<блок>/<имя>-<m|t|d>-<ширина>.<ext>`, ширины и кадры — `tools/photos_site.json` (этап 1).
  Тон «фото с цветом» **запечён в файлы** (решение этапа 1) — CSS-фильтров и наложений на фото нет; затемнения кадров — CSS-градиенты блока.
- Инструменты живут **вне `site/`**, в `Доработка/вёрстка/tools/`: Node (`sharp` — фото), Python (`fonttools` — сабсет шрифтов,
  Playwright — скриншоты и видео для сверки). Установлены Node 24, npm 11, Python 3.12, git.

## Брейкпойнты и масштаб (из ПЕРЕДАЧА, раздел 1)

- `< 600` — телефон (макет 390), `600–1023` — планшет (834), `≥ 1024` — десктоп (1440). CSS — mobile-first.
- Крупные роли — **от колонки** (решение этапа 0): кегль = N × `--u`, `--u` = (окно − 2 поля) / колонка макета 358 / 770 / 1312.
  Телефон: пол — значение на 360, потолок — окно 480; планшет — без потолка; десктоп — до окна 1920. Гигант не меньше 38.
  Окно — `--vw` (1 % `clientWidth` без скроллбара, скрипт в `<head>`). Роли — `site/css/base.css`, утверждены на `tools/roles.html`.
- Фиксированы: капс 12, метка 11, поле формы 16, лид и ссылка 24 / 30, поля страницы 16 / 32 / 64.
- Шире 1440 — **vw до 1920, дальше потолок** (решение 2026-10-02): шире 1920 композиция 1920 по центру (`.wrap`), фон секций в край.
- Проверяемые ширины: **360, 390, 600, 834, 1023, 1024, 1280, 1440, 1920**. Горизонтального скролла страницы нет ни на одной.

## Поведение (сводка, подробности — ПЕРЕДАЧА 3–4 и заметки блоков)

- **Вход по скроллу:** верх элемента на 90 % экрана, один раз, доигрывает сам. Анимируются только `transform`, `opacity` и `clip-path`.
  Три типа: гигант (сборка из букв), текст (проявление строками), фото (scale в рамке).
- **`prefers-reduced-motion`:** кадр покоя, а смены состояний — мгновенно или через opacity ≤ 0,2 с.
- **Без JS** страница читается целиком в покое: стартовые состояния анимаций выставляет JS, а не CSS по умолчанию (`html.js`).
  Страховка (Д1): модули не загрузились — класс `js` снимается (полноценный режим «без JS»), входы не запустились за 3 с — `no-motion`.
- **Телефон и планшет:** наведения нет, всё видно без жеста. Тапы — 08 и пункты 05 / 10. Свайпы — 05 / 10 (`touch-action: pan-y`).
  Карусель 03 — `scroll-snap` без JS (JS — только счётчик).
- **Десктоп:** наведения только под `@media (hover: hover) and (pointer: fine)`. Ещё на десктопе:
  - sticky «БАЛЫ» через шов Hero → Форматы;
  - закрепление 02 при скролле — sticky плюс смена шага по IntersectionObserver, без скраба;
  - закрепление 05 при скролле (решение этапа 4) — та же механика, смена формата занавесом;
  - автосмена 10 каждые 4 с, пауза при наведении, вне экрана и при reduced-motion;
  - клики в 08.

  Всё это — по заметкам десктопа в Figma.
- **Шапка:** единственный `position: fixed`, на всех ширинах только логотип и «Меню» (П-01), вариант «Над светлым» по `data-header="light"`.
- **Меню:** полноэкранная шторка. Фокус удерживается внутри, Esc закрывает, скролл страницы заблокирован без прыжка,
  страница под шторкой — `inert` (без `aria-modal`).
  Пункт закрывает шторку и ведёт к якорю.
- **Форма:** полноэкранный лист (`<dialog>` + `showModal()`), поля 16, подписи над полями, `:focus-visible` — линия 2 px.
- Высоты: hero `100svh − 64px` (телефон, планшет), меню и форма `100dvh`, у обоих запасное значение `vh`. Десктоп — каждый блок ровно в окно (Д2, ниже).

## Приёмы вёрстки

Координаты из кадров × `--u` / `--s`, состояния `data-state`, входы `motion.js`, переключатель `switch.js`, система «в экран» (Д2),
шапки и экраны тела (Д3а–Д3в) — в **`ПРИЁМЫ.md`**. Читать перед вёрсткой или правкой блока.

## Доступность и типографика

- Семантика: один `h1` (hero), `h2` у каждого раздела, `nav`, `main`, `footer`. Языковой атрибут — `ru`.
- Гиганты, разбитые на буквы: обёртка с `aria-label="слово"`, сами буквы — `aria-hidden`. Вертикальные гиганты телефона
  удобнее делать через `writing-mode: vertical-rl; transform: rotate(180deg)`: так коробка занимает место в потоке. Сверить с кадром.
- Переносы внутри слов в гигантах запрещены: `hyphens: none`, `word-break: keep-all`, `white-space: nowrap` по ситуации.
- Неразрывные пробелы после однобуквенных предлогов и союзов и перед тире ставить можно — это не правка текста.
  Кавычки, «ё» и регистр — как в Figma.
- Контраст по ПЕРЕДАЧА 2: мелкий текст на Terra, Ash и Slate — Greige Light. Зоны нажатия ≥ 44 × 44.

## Бюджет качества (проверка — этап 7)

- Lighthouse mobile: Performance ≥ 90, Accessibility / Best Practices / SEO ≥ 95.
- LCP ≤ 2,5 с (hero-фото — `fetchpriority="high"`, preload), CLS ≤ 0,05 (у всех медиа `width` / `height` или `aspect-ratio`).
- Первый экран ≤ 1 МБ; фото ниже первого экрана — `loading="lazy"` и `decoding="async"`. JS ≤ 40 КБ без минификации.
- Браузеры: Safari iOS, Chrome Android, Яндекс Браузер, Chrome / Firefox / Safari / Edge на десктопе — последние две версии.
  Сверка — только Playwright `chromium` и `webkit`; проверки на телефоне и старых iOS нет (решение пользователя 2026-10-04).

## Как сверяем блок

Процедура, инструменты и проверочные окна — скилл **`baly-sverka`**. Коротко: сначала таблица отклонений (порог 4 px), картинки пар — только для кадров
сверх порога; движение и вкус пользователь смотрит сам в Chrome (`python tools/serve.py` → `http://127.0.0.1:8080/site/`).
После «да» — запись в ЖУРНАЛ: что сделано, файлы, отступления от макета, флаги.

## Что НЕ трогать

- Figma — **только чтение**. Макет, кадры адаптива и стили не менять. Если в макете нашлась ошибка, это флаг в ЖУРНАЛ и вопрос пользователю.
- Текст не менять. Вопросы по тексту уже собраны в `../адаптив/ПЕРЕДАЧА.md`, раздел 7; новые — дописывать туда же.
- `Прототип/` — старый дизайн (Manrope, схемы). Брать из него можно только служебное: структуру мета-тегов и OG, текст `privacy.html`.
  Вёрстку, стили, скрипты и схемы — нельзя. Favicon-ромб нарисован по схеме 01, а схем в v2 нет: значок сделать заново из логотипа.
- `assets/` — оригиналы фото. Не менять и не удалять, всё производное класть в `site/img/`.
