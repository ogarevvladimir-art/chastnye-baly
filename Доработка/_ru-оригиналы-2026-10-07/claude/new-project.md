# Новый проект

Порядок и принципы — инструкция пользователя `C:\Users\ogare\Desktop\Мои документы\VS CODE\Работа с Claude — большие проекты.md`
(разделы 1–3, 9, 15, 19). Здесь — процедура. Пишем по-русски, имена папок и файлов — как у пользователя (кириллица допустима).

## 1. Вопросы (одним AskUserQuestion, 3–4 вопроса; на языке пользователя)

1. **Тип проекта:** сайт по макету / макет в Figma / 3D-модель и чертежи (SketchUp) / подборка или презентация / видео.
2. **Где папка:** обычно `C:\Users\ogare\Desktop\Мои документы\Plyaskin group\<Название>` или `…\VS CODE\<Название>`.
3. **Источник правды и результат:** что главное (Figma-файл, бриф, размеры, сценарий) и что сдаём (папка `site/`, PDF, модель, рендер).
4. **Нужен ли git** (для подборок и презентаций — по желанию; для сайта и моделей — да).

Название, заказчика и цель обычно уже есть в просьбе — не переспрашивать.

## 2. Проверки до создания

- Папка уже есть? Посмотреть содержимое; ничего не перезаписывать, только добавлять.
- Уже есть `CLAUDE.md` / `STATUS.md` / `.git`? Есть — продолжать их, а не заводить заново. Есть `.git` — посмотреть `git log`, `git remote -v`, `git status`
  и рассказать пользователю, что нашлось.

## 3. Структура по типу

| Тип | Папки и файлы |
|---|---|
| Сайт по макету | `site/` (только то, что заливается), `assets/` (оригиналы фото), `Макет/референс/`, `Доработка/<работа>/` с `ОБЩЕЕ.md`, `ПЛАН.md`, `ЖУРНАЛ.md`, `ПРАВКИ.md`, `журнал/`, `tools/` |
| Макет в Figma | `Макет/референс/`, `Доработка/<работа>/` (ОБЩЕЕ, ПЛАН, ЖУРНАЛ, ПРАВКИ, `журнал/`), ссылка на файл Figma в CLAUDE.md |
| 3D-модель / SketchUp | `ОБЩЕЕ.md` (модули, размеры, материалы, оси), `скрипты/`, `done/` (готовые скрипты, модель пересобирается с нуля), `отчёты/`, `ЖУРНАЛ.md`; работа через скилл `sketchup-layout` |
| Подборка / презентация | `Бриф.md` (задача, аудитория, стиль, пара шрифтов), `Фото/`, `Результат/` (версии PDF с датой в имени), `ЖУРНАЛ.md` |
| Видео | `STORYBOARD.md`, исходники композиции; дальше ведёт скилл `hyperframes` |

Пустые рабочие файлы не плодить: создать только те, что нужны с первого этапа; `ПРАВКИ.md` — когда начнётся сбор правок.

## 4. CLAUDE.md (в корне, коротко)

```markdown
# <Проект>

<Одна строка: что делаем, для кого, что сдаём.> Где остановились — в `STATUS.md`.

## Начало сессии
1. `STATUS.md`.
2. <рабочие файлы: ОБЩЕЕ, раздел текущего этапа в ПЛАН, ЖУРНАЛ — только текущая работа>.
3. Скиллы: <какие и когда>.

## Конец сессии
- STATUS.md — коротко: закрыто / ждёт пользователя / следующий шаг.
- ЖУРНАЛ — запись этапа. Принятый этап — в `журнал/<этап>.md`.
- Git — коммит по просьбе, тег на принятом этапе. На GitHub — только по явной просьбе.

## Карта папок
| Папка | Что там |
|---|---|

## Источник правды
- <где, что делать при расхождении — спросить пользователя>

## Правила проекта
- <стиль, запреты, решения — заполняется по ходу>

## Как работаем
- Вопросы → бриф → этап отдельной сессией → «да» → следующий.
- Варианты — сначала одним кадром или словами, с рекомендацией.
- Проверки — числами, картинки по порогу.
- Механика по готовому решению — агенту `executor`.
```

## 6. Git (если нужен)

1. `git init`, `git config core.quotepath false` (русские имена в выводе).
2. `.gitignore` — основа ниже плюс строки типа проекта.
3. `.gitattributes` для Windows: `* text=auto eol=lf` и `binary` для jpg / png / webp / pdf / docx / ttf / woff2 / mp4.
4. Первый коммит «Проект заведён: структура, CLAUDE.md, STATUS.md» — с подписью соавторства из системных инструкций.
5. Удалённый репозиторий не создавать и не пушить без явной просьбы.

```
# Производное и кэши
node_modules/
__pycache__/
*.pyc
.cache/
.figma-shots/
сверка/
_figma/
# Тяжёлое
*.mp4
*.mov
*.zip
*.rar
*.psd
# Секреты
**/_private/
*.env
секреты.txt
# Системное
Thumbs.db
desktop.ini
```

По типу: сайт — `tools/node_modules/`; SketchUp — `*.skb` (автокопии); подборка — `Фото/исходники/`, если они тяжёлые.

## 7. Память

Добавить файл-указатель в память текущей рабочей папки и строку в `MEMORY.md`:
«<Проект> — перед работой читать CLAUDE.md и STATUS.md в `<путь>`; ход этапов в память не писать».
Ход работы, статус и решения — только в файлах проекта.

## 8. Итог пользователю

Коротко: что создано (дерево папок), что нашлось из уже существующего, первый шаг (обычно — бриф и вопросы этапа 0)
и как начинать следующие сессии: «Продолжаем <проект>, прочитай STATUS.md» / "Continue <project>, read STATUS.md"
(если сессия открыта в папке проекта, STATUS.md подгрузит хук сам).
Отвечать на языке пользователя: пишет по-английски — итог и вопросы по-английски.
