# Сверка сайта «Частные балы»

Папка инструментов — `Plyaskin group/Частные балы сайт/Доработка/вёрстка/tools/`, команды запускаются из `Доработка/вёрстка/`.
Скриншоты сверок — `сверка/<этап>/` (в git не хранятся). Кадры Figma плагин пишет в `VS CODE/.figma-shots/`.

## Порядок — сначала числа

1. **Таблица отклонений.** Скрипт сверки этапа (`tools/<этап>_compare.py`, образец — `d3v_compare.py`) печатает строку на кадр
   и итог «наибольшее отклонение N px, кадров > 4 px: M». Порог — **4 px** по позиции и кеглю. Прогнать в обоих движках: без флага и `-b webkit`.
2. **Картинки — только для кадров сверх порога**, и только нужная пара (`сверка/<этап>/pair_<движок>_<окно>.png`, сверху Figma, снизу сайт).
   Все листы подряд не открывать. Расхождение объяснить (например, антиква в браузере чуть уже Figma) или исправить.
3. **Поведение — автотесты**, их вывод тоже числа: `pilot_check.py`, `stage3_check.py`…`stage5_check.py`, `d1_check.py` (каждый — chromium и webkit).
4. **Вкус и движение смотрит пользователь** в Chrome — десктоп и режим устройства (F12 → Ctrl+Shift+M): `python tools/serve.py`
   → `http://127.0.0.1:8080/site/` (из `file://` модули не грузятся). Claude видео и рендеры «на глаз» не разбирает без просьбы.
5. После «да» — запись в ЖУРНАЛ: что сделано, файлы, отступления от макета, флаги; итог регрессии одной строкой на скрипт.

## Инструменты

| Задача | Команда |
|---|---|
| Сервер | `python tools/serve.py` (`--lan` — для телефона в той же сети) |
| Скриншоты сайта | `python tools/shots.py -w 390 834 1440 -b chromium webkit [-s <селектор блока>] [--viewport] [--motion] -o <папка>` |
| Пара «Figma \| сайт» | `python tools/pair.py figma.png site.png -o out.png [--diff]` |
| Сверка этапа | `python tools/<d2|d3a|d3b|d3_02|d3v>_compare.py [-b webkit]` |
| Доступность | `python tools/axe_check.py [-w 1440 -b webkit]` (по умолчанию 390 / 834 / 1440, chromium) |
| LCP | `python tools/lcp.py` (без замедления и CPU ×4 + сеть 1,6 Мбит/с) |
| Набор против Figma | `python tools/type_check.py` |

Новая сверка этапа — копия ближайшего `*_compare.py`: точки Figma (левый верхний угол узла) — в `сверка/<этап>/figma_points.json`,
выгрузка дерева — один раз за этап (`--tree`).

## Окна и ширины

- Проверочные окна десктопа: **1440×900, 1920×950, 1366×650, 1280×600, 1024×650** (опорное — 1440×900, там s = u = 1).
- Ширины без горизонтального скролла: **360, 390, 600, 834, 1023, 1024, 1280, 1440, 1920** — в том числе во время входов
  (скролл к блоку −200 и замер через 250 мс).

## Грабли Playwright и WebKit

- WebKit под Windows не применяет оси variable-шрифтов → Unbounded статичными 400 / 700.
- WebKit не снимает картинку выше 32 767 px (`shots.py` режет кусками). `full_page`-снимок теряет фото за окном — склейка экранов сдвигом body (`shots.py`).
- Постоянный `scrollbar-gutter` сужает headless-окно на 15 px. Плавный скролл в тестах запускает входы — `behavior: 'instant'`.
  Перед `reload` — `history.scrollRestoration = 'manual'`, иначе вход стартует до паузы раскадровки.
- Курсор теста под fixed-шапкой не наводит. Длинный снимок элемента не дорисовывает ленту карусели — снимать в окне высоты секции.
- Свайп в тестах — синтетические PointerEvent с `pointerType: 'touch'`. Раскадровка — `document.getAnimations()` на паузе в 0 / 25 / 100 %.
- Вертикальное письмо внутри абсолютного слоя в WebKit берёт высоту и длину строки от окна — задавать явно. Растянутые буквы входа дают горизонтальный скролл — `overflow-x: clip`.
- Неразрывные пробелы Figma в узкой колонке дают горизонтальный скролл только с JS — искать отключением секций.
- Ряд `0fr` + `align-items: start` — невидимый элемент перекрывает соседнюю строку (`align-self: stretch`).
- WebKit не учитывает `flex-basis` в ширине абсолютного flex-контейнера по содержимому — ширину задавать `width` и `flex: none`.
- `modulepreload` на телефоне ухудшает LCP фото hero.
- С телефона по Wi-Fi сайт не открылся: порт 8080 закрыт (брандмауэр / AmneziaVPN).
