## Stack

- **Plain HTML, CSS and JS, no framework, no build step.** One page `index.html` plus `privacy.html` and `404.html`.
- CSS — several files by layer (see structure). No frameworks or preprocessors. Custom properties, `clamp()`,
  media queries at breakpoints 600 / 1024.
- JS — ES modules (`<script type="module">`) without a bundler. No jQuery, GSAP or Lenis: the design has no scroll scrubbing.
  Entrance animations — IntersectionObserver + Web Animations API / CSS transitions.
- Native scrolling, no "smooth scroll".
- Fonts — **self-hosted, no Google Fonts** (Google requests from Russia are slow and send IPs abroad). Unbounded (OFL, static 400 and 700 cuts
  from the variable font — stage 2) and Old Standard TT Regular + Italic, Latin + Cyrillic subset, `woff2`, `font-display: swap`, preload of the two main files
  (Unbounded Bold, Old Standard Regular).
- Photos — AVIF + WebP + JPEG via `<picture>` and `srcset` for 1× / 2× / 3×. Crops — separate files per layout
  (`<source media>`): `site/img/<block>/<name>-<m|t|d>-<width>.<ext>`, widths and crops — `tools/photos_site.json` (stage 1).
  The "photo with colour" tone is **baked into the files** (stage 1 decision) — no CSS filters or overlays on photos; frame shading — block CSS gradients.
- Tools live **outside `site/`**, in `Доработка/вёрстка/tools/`: Node (`sharp` — photos), Python (`fonttools` — font subsetting,
  Playwright — screenshots and video for comparison). Installed: Node 24, npm 11, Python 3.12, git.

## Breakpoints and scale (from ПЕРЕДАЧА, section 1)

- `< 600` — phone (design 390), `600–1023` — tablet (834), `≥ 1024` — desktop (1440). CSS is mobile-first.
- Large roles scale **from the column** (stage 0 decision): size = N × `--u`, `--u` = (window − 2 margins) / design column 358 / 770 / 1312.
  Phone: floor — the value at 360, ceiling — window 480; tablet — no ceiling; desktop — up to window 1920. Giant type not below 38.
  Window — `--vw` (1 % of `clientWidth` without the scrollbar, script in `<head>`). Roles — `site/css/base.css`, approved on `tools/roles.html`.
- Fixed: caps 12, label 11, form field 16, lead and link 24 / 30, page margins 16 / 32 / 64.
- Wider than 1440 — **vw up to 1920, then capped** (decision 2026-10-02): above 1920 a 1920 composition centred (`.wrap`), section backgrounds full-bleed.
- Checked widths: **360, 390, 600, 834, 1023, 1024, 1280, 1440, 1920**. No horizontal page scroll at any of them.

## Behaviour (summary; details — ПЕРЕДАЧА 3–4 and block notes)

- **Scroll entrance:** element top at 90 % of the viewport, once, plays to the end. Only `transform`, `opacity` and `clip-path` animate.
  Three types: giant (assembled from letters), text (revealed by lines), photo (scale inside its frame).
- **`prefers-reduced-motion`:** rest frame; state changes instant or via opacity ≤ 0.2 s.
- **Without JS** the whole page reads at rest: JS sets the animation start states, not default CSS (`html.js`).
  Safety net (Д1): modules failed to load — the `js` class is removed (full "no JS" mode); entrances didn't start within 3 s — `no-motion`.
- **Phone and tablet:** no hover, everything visible without gestures. Taps — 08 and items in 05 / 10. Swipes — 05 / 10 (`touch-action: pan-y`).
  Carousel 03 — `scroll-snap` without JS (JS only for the counter).
- **Desktop:** hovers only under `@media (hover: hover) and (pointer: fine)`. Also on desktop:
  - sticky «БАЛЫ» across the Hero → Форматы seam;
  - 02 pinned on scroll — sticky plus step change via IntersectionObserver, no scrubbing;
  - 05 pinned on scroll (stage 4 decision) — same mechanism, format change via a curtain;
  - 10 auto-advances every 4 s, pauses on hover, off-screen and with reduced-motion;
  - clicks in 08.

  All per the desktop notes in Figma.
- **Header:** the only `position: fixed`; at all widths only the logo and «Меню» (П-01); the «Над светлым» (over light) variant via `data-header="light"`.
- **Menu:** full-screen curtain. Focus trapped inside, Esc closes, page scroll locked without a jump,
  the page under the curtain is `inert` (no `aria-modal`).
  An item closes the curtain and goes to its anchor.
- **Form:** full-screen sheet (`<dialog>` + `showModal()`), fields 16, labels above fields, `:focus-visible` — a 2 px line.
- Heights: hero `100svh − 64px` (phone, tablet), menu and form `100dvh`, both with a `vh` fallback. Desktop — every block exactly one window (Д2).

## Accessibility and typography

- Semantics: one `h1` (hero), an `h2` per section, `nav`, `main` (no `footer` since Ц4: the finale ends the page). Language attribute — `ru`.
- Giant words split into letters: wrapper with `aria-label="word"`, the letters `aria-hidden`. Vertical giants on phone
  are easier with `writing-mode: vertical-rl; transform: rotate(180deg)`: the box then takes space in the flow. Check against the frame.
- No hyphenation inside giant words: `hyphens: none`, `word-break: keep-all`, `white-space: nowrap` as needed.
- Non-breaking spaces after one-letter prepositions and conjunctions and before dashes are allowed — that isn't a copy edit.
  Quotes, «ё» and letter case — as in Figma.
- Contrast per ПЕРЕДАЧА 2: small text on Terra, Ash and Slate — Greige Light. Tap targets ≥ 44 × 44.

## Quality budget (checked in stage 7)

- Lighthouse mobile: Performance ≥ 90, Accessibility / Best Practices / SEO ≥ 95.
- LCP ≤ 2.5 s (hero photo — `fetchpriority="high"`, preload), CLS ≤ 0.05 (all media have `width` / `height` or `aspect-ratio`).
- First screen ≤ 1 MB; photos below the first screen — `loading="lazy"` and `decoding="async"`. JS ≤ 40 KB unminified.
- Browsers: Safari iOS, Chrome Android, Yandex Browser, Chrome / Firefox / Safari / Edge on desktop — last two versions.
  Comparison — Playwright `chromium` and `webkit` only; no phone or old-iOS testing (user decision 2026-10-04).
