# Вёрстка сайта «Частные балы»

Цель — одностраничный сайт по макету v2 (десктоп 1440, планшет 834, телефон 390), готовый к заливке на хостинг.
**Готовый к деплою проект — папка `Частные балы сайт/site/`**: в ней лежит ровно то, что заливается на сервер, и ничего больше.
План, журнал, инструменты и сверки — здесь, в `Доработка/вёрстка/`.

## Решения пользователя (2026-10-02)

1. **Хостинг — российский с PHP** (Beget / Timeweb / REG.RU). Папка `site/` заливается целиком по FTP / SFTP, Apache + `.htaccess`.
2. **Куда уходят заявки — решить позже.** До этапа 6 форма — интерфейс с состояниями; обработчик `send.php` подключается на этапе 6.
3. **Аналитика — решить позже.** Место под счётчик и плашку cookie закладывается, подключение — на этапе 6 или 7.

## Стек

- **Чистые HTML, CSS и JS, без фреймворка и без сборки.** Одна страница `index.html` плюс `privacy.html` и `404.html`.
- CSS — несколько файлов по слоям (см. структуру). Фреймворков и препроцессоров нет. Нужны custom properties, `clamp()`,
  container-free медиазапросы по брейкпойнтам 600 / 1024.
- JS — ES-модули (`<script type="module">`) без бандлера. Без jQuery, GSAP и Lenis: скраба по скроллу в макете нет.
  Анимации входа — IntersectionObserver + Web Animations API / CSS-переходы.
- Прокрутка нативная, без «плавного скролла».
- Шрифты — **свои, без Google Fonts** (запросы к Google из РФ медленные и передают IP за рубеж). Unbounded (OFL, статичные срезы 400 и 700
  из variable — этап 2) и Old Standard TT Regular + Italic, сабсет латиница + кириллица, `woff2`, `font-display: swap`, preload двух основных файлов
  (Unbounded Bold, Old Standard Regular).
- Фото — AVIF + WebP + JPEG через `<picture>` и `srcset` под 1× / 2× / 3×. Кропы — отдельные файлы под каждую раскладку
  (`<source media>`): `site/img/<блок>/<имя>-<m|t|d>-<ширина>.<ext>`, ширины и кадры — `tools/photos_site.json` (этап 1).
  Тон «фото с цветом» **запечён в файлы** (решение этапа 1) — CSS-фильтров и наложений на фото нет; затемнения кадров — CSS-градиенты блока.
- Инструменты живут **вне `site/`**, в `Доработка/вёрстка/tools/`: Node (`sharp` — фото), Python (`fonttools` — сабсет шрифтов,
  Playwright — скриншоты и видео для сверки). Установлены Node 24, npm 11, Python 3.12, git.

## Поведение (сводка, подробности — ПЕРЕДАЧА 3–4 и заметки блоков)

- **Вход по скроллу:** верх элемента на 90 % экрана, один раз, доигрывает сам. Анимируются только `transform`, `opacity` и `clip-path`.
  Три типа: гигант (сборка из букв), текст (проявление строками), фото (scale в рамке).
- **`prefers-reduced-motion`:** кадр покоя, а смены состояний — мгновенно или через opacity ≤ 0,2 с.
- **Без JS** страница читается целиком в покое: стартовые состояния анимаций выставляет JS, а не CSS по умолчанию (`html.js`).
  Страховка (Д1): модули не загрузились — класс `js` снимается (полноценный режим «без JS»), входы не запустились за 3 с — `no-motion`.
- **Телефон и планшет:** наведения нет, всё видно без жеста. Тапы — 08 и пункты 05 / 10. Свайпы — 05 / 10 (`touch-action: pan-y`).
  Карусель 03 — `scroll-snap` без JS (JS — только счётчик).
- **Десктоп:** наведения только под `@media (hover: hover) and (pointer: fine)`. Ещё на десктопе:
  - sticky «БАЛЫ» через шов Hero → Форматы;
  - закрепление 02 при скролле — sticky плюс смена шага по IntersectionObserver, без скраба;
  - закрепление 05 при скролле (решение этапа 4) — та же механика, смена формата занавесом;
  - автосмена 10 каждые 4 с, пауза при наведении, вне экрана и при reduced-motion;
  - клики в 08.

  Всё это — по заметкам десктопа в Figma.
- **Шапка:** единственный `position: fixed`, на всех ширинах только логотип и «Меню» (П-01), вариант «Над светлым» по `data-header="light"`.
- **Меню:** полноэкранная шторка. Фокус удерживается внутри, Esc закрывает, скролл страницы заблокирован без прыжка,
  страница под шторкой — `inert` (без `aria-modal`).
  Пункт закрывает шторку и ведёт к якорю.
- **Форма:** полноэкранный лист (`<dialog>` + `showModal()`), поля 16, подписи над полями, `:focus-visible` — линия 2 px.
- Высоты: hero `100svh − 64px` (телефон, планшет), меню и форма `100dvh`, у обоих запасное значение `vh`. Десктоп — каждый блок ровно в окно (Д2, ниже).

## Приёмы пилота (этап 2, 2026-10-03) — дальше не меняются

- **Координаты блока — из кадра Figma, умноженные на `--u`.** Телефон и планшет — поток (grid / flex) с отступами из кадра (`calc(N * var(--u))`);
  десктоп — композиция 1440: точка x → `calc(var(--x0) + (x − 64) * var(--u))`, y → `y * var(--u)`. Шире 1920 всё стоит по центру через `--edge`.
- **Состояния десктопа** (наведения, клики) — `data-state` на секции; всё, что меняется, — `transform`, `opacity`, `clip-path` из координат кадров
  состояний, 0,35 с `--ease-state`. Мышь — `pointerenter`, клавиатура — `focusin` внутри части, касание на широком экране — тап. Скрытые
  в покое ссылки остаются фокусируемыми (opacity, не visibility).
- **Части, которые раздвигаются** (половины, панели), — слои во всю ширину с `clip-path: inset()`: хит-тест идёт по clip-path, граница
  наведения переезжает сама.
- **Входы — `motion.js`, атрибуты в разметке:** `data-giant` (сборка, (n+1) × 1em, 0,15 + 0,05n с, 0,8 с expo-out), `data-reveal="text"` / `"fade"`,
  `data-photo` (img scale 1,1 → 1), `data-reveal="bar"` (scaleX 0 → 1), `data-delay`. Вертикальный гигант — тот же `data-giant` в элементе с
  `writing-mode: vertical-rl; transform: rotate(180deg)` (этап 3: слово занимает место в потоке; `motion.js` сам переключается на translateY / scaleY). Стартовые
  состояния — `motion.css` под `html.js:not(.no-motion)` и `prefers-reduced-motion: no-preference`.
- **Затемнения и «Тон» — CSS-градиенты блока**, профиль снимается подгонкой рендера Figma к файлу из `site/img/` (`tools/overlay_profile.py`
  и подгонка цвета в ЖУРНАЛ этапа 2): плагин не отдаёт стопы градиентов. Цвет «Тона» — поверхность части (`--surf-rgb`), не Ink.
- **Фото, файл которого шире окна** (запас под состояния): окно `overflow: hidden`, `<picture>` внутри со сдвигом и размером файла в `--u`;
  где кроп этапа 1 переставлен (override), положение файла искать сравнением окна Figma с файлом (OpenCV `matchTemplate`), а не по `photos_site.json`.
- **Зона нажатия ссылки** — сама ссылка во всю строку колонки с `padding-block: 8px` и компенсацией отступами, без псевдоэлементов
  (псевдоэлемент шире колонки даёт горизонтальный скролл на 360).
- **Сверка блока:** `tools/pilot_shots.py` как образец — кадры сайта в окне высоты кадра Figma (десктоп 1440 × 932), ленивые фото грузятся заранее,
  раскадровка — `document.getAnimations()` на паузе в момент 0 / 25 / 100 %; поведение — автотест по образцу `tools/pilot_check.py` в chromium и webkit.
- **Шрифты — только статичные срезы** (Unbounded 400 / 700): WebKit под Windows не применяет оси variable-шрифтов.

## Приёмы доработки Д2 (2026-10-04) — система «в экран», дальше не меняются

Утверждена пользователем (вариант B, секция Figma `302:1492`, заметка `302:2175`). Правило П-04: **каждый десктопный блок — ровно в окно**.

- **Блок десктопа = окно:** `height: 100vh; height: 100svh`. Шапка 72 лежит поверх; верхняя линия содержимого — **104 px** (72 + 32).
- **Две единицы:** x и колонки — × `--u` (как было); y, гиганты и антиква — × **`--s` = min(u, высота окна / 900)** (`tokens.css`, только десктоп).
  Опорный кадр — **1440 × 900**: там s = u = 1, координаты кадров Figma переносятся как есть. Привязка к низу блока — `calc(100% − N * var(--s))`.
- **Фиксированы (px):** мелкий текст (капс 12, Body 12, ссылка 30), верхняя линия 104, отступы от краёв частей.
- **Порядок ужатия на низком окне:** фото забирает остаток высоты (окно фото от N·s до низа), гигант и антиква уменьшаются по s, мелкий текст
  не меняется. Нижнего предела нет, прокрутки внутри блока нет.
- **Мелкий текст переносится, а не наезжает:** колонка описания — `min(392px, 392 × окно / 1440)`; строка «номер + текст» в покое прижата низом
  (`translate(…, calc(Y − 100%))` — длинный текст уходит вверх), в наведении — верхом на линии 104.
- **Р-15 — поля шире 1440:** отступ от края части (ось, граница половины, правый край страницы) — фиксированные 64 / 72 px, а не × u.
- **Что зависит от высоты текста** (длина описания) — меряет JS и кладёт в переменную (`--drop`, `--lw-p` / `--lw-c` в `hf.js`); значение по умолчанию — в CSS.
- **Проверочные окна** (видимая область браузера): 1440×900, 1920×950, 1366×650, 1280×600, 1024×650. Сверка — `tools/d2_compare.py` (пары «Figma | сайт»
  и цифры против узлов кадров, порог 4 px), поведение — раздел «Д2» в `tools/pilot_check.py` (блок = окно, всё нужное в окне, гигант не на тексте,
  телефон и планшет — поток).
- **Грабли:** WebKit не учитывает `flex-basis` в ширине абсолютного flex-контейнера по содержимому и сжимает соседний текст — ширину задавать `width`
  и `flex: none`. На низких окнах окно фото поднимается к тексту — текстовым слоям `z-index: 1` над фото.
- **Figma:** утверждённое правится в действующих кадрах (`191:626` — автолейаут: высоты блоков сдвигают страницу сами), варианты — секцией под Frame 5.
  На 1440 × 900 s = 1: меняются только высоты кадров и y, привязанные к низу.

### Д3а (2026-10-05): шапка раздела и блоки в два экрана

- **Экран — `--scr`** (`tokens.css`: 100vh → 100svh). Блок в два экрана (шапка отдельно) — `.sh` высотой `--scr`, тело — вторым экраном
  (01 — `min-height: 2 × --scr`, 04 — сцена `--scr − 285s` + низ 285s).
- **Шапка раздела «в экран»:** метка на 104; строки H2 — 104 + 56s и 104 + 176s, кегль 150s; лид — от оси (`x0 + 656u`), y × s.
  Всё абсолютным позиционированием от верха экрана.
- **Что ужимается сверх s, считает JS:** 03 — `--kh` = min(s, (верх колонок − 24 − 104) / 296), колонки стоят от низа по фактической высоте
  (`blocks.js`, ResizeObserver). 01 — шаг строк = min(128s, (экран − 259) / 5): пять строк + раскрытие самого длинного описания (90 + 40) в экране.
- **Высоты текста в генераторе Figma — по факту, не по формуле** (строки текста считать нельзя: Unbounded в Figma на ~5 % шире веб-шрифта,
  подписи переносятся по-разному). Мелкий текст колонок — `min(416 px, колонка)`; подпись шире колонки переносится (03 на 1024).
- **Сверка** — `tools/d3a_compare.py` (кадры секции `307:2595`, точки — `сверка/d3a/figma_points.json`); номер шага 01 сравнивается зазором от слова.

## Доступность и типографика

- Семантика: один `h1` (hero), `h2` у каждого раздела, `nav`, `main`, `footer`. Языковой атрибут — `ru`.
- Гиганты, разбитые на буквы: обёртка с `aria-label="слово"`, сами буквы — `aria-hidden`. Вертикальные гиганты телефона
  удобнее делать через `writing-mode: vertical-rl; transform: rotate(180deg)`: так коробка занимает место в потоке. Сверить с кадром.
- Переносы внутри слов в гигантах запрещены: `hyphens: none`, `word-break: keep-all`, `white-space: nowrap` по ситуации.
- Неразрывные пробелы после однобуквенных предлогов и союзов и перед тире ставить можно — это не правка текста.
  Кавычки, «ё» и регистр — как в Figma.
- Контраст по ПЕРЕДАЧА 2: мелкий текст на Terra, Ash и Slate — Greige Light. Зоны нажатия ≥ 44 × 44.

## Бюджет качества (проверка — этап 7)

- Lighthouse mobile: Performance ≥ 90, Accessibility / Best Practices / SEO ≥ 95.
- LCP ≤ 2,5 с (hero-фото — `fetchpriority="high"`, preload), CLS ≤ 0,05 (у всех медиа `width` / `height` или `aspect-ratio`).
- Первый экран ≤ 1 МБ; фото ниже первого экрана — `loading="lazy"` и `decoding="async"`. JS ≤ 40 КБ без минификации.
- Браузеры: Safari iOS, Chrome Android, Яндекс Браузер, Chrome / Firefox / Safari / Edge на десктопе — последние две версии.
  Сверка — только Playwright `chromium` и `webkit`; проверки на телефоне и старых iOS нет (решение пользователя 2026-10-04).

## Как сверяем блок

1. Рендер Figma: покой 390 / 834 / 1440, состояния, раскадровки и заметки. Сохранить в `.figma-shots/` с префиксом этапа
   (`v<N>_…`), скопировать в `сверка/`.
2. Скриншоты сайта Playwright на 360 / 390 / 834 / 1440 (и 1024, где композиция на грани) → `сверка/<блок>/site_<ширина>.png`.
3. Пары «Figma | сайт» склеить одной картинкой (`tools/pair.py`) и показать пользователю. Расхождение больше 4 px
   в позиции или кегле объяснить или исправить.
4. Движение: видео Playwright (`record_video_dir`) на 390 и 1440. Плюс пользователь смотрит в Chrome — десктоп и режим устройства
   (F12 → Ctrl+Shift+M): `python tools/serve.py`, адрес `http://127.0.0.1:8080/site/` (не `file://` — модули не загрузятся).
5. После «да» — запись в ЖУРНАЛ: что сделано, файлы, отступления от макета, флаги.

## Что НЕ трогать

- Figma — **только чтение**. Макет, кадры адаптива и стили не менять. Если в макете нашлась ошибка, это флаг в ЖУРНАЛ и вопрос пользователю.
- Текст не менять. Вопросы по тексту уже собраны в `../адаптив/ПЕРЕДАЧА.md`, раздел 7; новые — дописывать туда же.
- `Прототип/` — старый дизайн (Manrope, схемы). Брать из него можно только служебное: структуру мета-тегов и OG, текст `privacy.html`.
  Вёрстку, стили, скрипты и схемы — нельзя. Favicon-ромб нарисован по схеме 01, а схем в v2 нет: значок сделать заново из логотипа.
- `assets/` — оригиналы фото. Не менять и не удалять, всё производное класть в `site/img/`.
