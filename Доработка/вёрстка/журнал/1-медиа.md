## 2026-10-02 — этап 1: медиа — фото и логотип

### Решения пользователя

1. **Тон «фото с цветом» запекается в файлы.** Кривая RGB → RGB (многочлен 3-й степени) подогнана на каждое фото по паре
   «кроп исходника | рендер Figma»: средняя ошибка 1–3 из 255, сдвиг цвета итоговых файлов против Figma ≤ 0,4. CSS-фильтров и наложений нет.
2. **Тон везде, как на 1440.** В кадрах 390 / 834 у hero, трёх фото 03 и 04 «Участники» стопку тона при сборке адаптива не перенесли
   (фото сырые) — на сайте они в тоне, как на десктопе.
3. **Чужие логотипы:** кропы без логотипа приняты (ниже); 03 «Группа» («Бал дебютантов» за головами) и 04 «Зрители»
   («ВМПАВТО / Бал…» за ведущим) — пока как в Figma, кропом не убираются → **нужна замена снимков**.
4. **Логотип утверждён:** SVG по обводке PNG, favicon и apple-touch — знак «P» из логотипа на Ink.

### Как устроено

- Каталог: 31 фото (32 картинки в Figma минус логотип) × раскладки 390 / 834 / 1440, включая кадры состояний (наведения, шаги 02,
  форматы 05, вечера 10). Узлы с картинками — `tools/figma_images.py` по выгрузкам `_figma/v1/tree_*.json`.
- Исходник найден для всех 31 (`tools/match_photos.py`): отбор по миниатюрам + многомасштабный поиск рендера внутри исходника (OpenCV).
  Два снимка нашлись только полным поиском: Форматы «корпоративные» — `KOR_0924_1.jpg`, 07 — `DSC03350_resized.jpg` (`_figma/v1/match_fixed.json`).
- В Figma часть фото загружена уже обрезанной и тонированной (`Доработка/фото-тон/`: 05 — 2400 × 1500, 10 — 640 × 800, 02 «05» — по рендеру);
  эти области учтены (`PRECROP` в `tools/photo_catalog.py`). Геометрия FILL сверена со всеми найденными рендерами — расхождение ≤ 0,7 %.
  CROP-узлы (03 «Симфонический» и «Группа» на 1440, 09 «Дама» везде) — по рендерам.
- Файл = объединение окон всех состояний раскладки; где окно покоя меньше файла (Форматы и 04 на 1440), его положение записано
  в `tools/photos_site.json` → `rest_in_frame`. Наведение-зум (05, 10: scale ≈ 1,06) — CSS, файл под незумленное окно.
- Карусель 03 на 390 / 834: рамка = карточка целиком (окно в макете урезано прокруткой ленты).
- Кропы без логотипов — `tools/photo_overrides.json`: Форматы «корпоративные» 1440 (с y 560), 03 «Духовой» 390 / 834 (с y 520, крупнее на 4 %),
  04 «Участники» 390 / 834 / 1440 (с y 480). Лист — `сверка/фото/v1_logotipy.jpg`.

### Флаги для следующих этапов

- Разметка: `<picture>` с `<source media>` на раскладку (m / t / d) × тип (avif, webp) и `<img>` JPEG; `srcset` по ширинам из `photos_site.json`,
  `sizes` — от кадра блока (кадры тянутся от колонки, см. `--u`). У всех — `width` / `height` кадра. Скрытые в покое фото (02 шаги 2–5,
  05 «совместный» и «номер», 10 «Кашемир») — `loading="lazy"`.
- На 1440 у Форматов и 04 файл шире окна покоя (`rest_in_frame`): окно — `overflow: hidden`, фото сдвинуто внутри.
- Затемнения кадров (hero «Затемнение кадра» 45 %, Форматы «Тон», 02 «Зал сверху») в файлы **не** запечены — это CSS-градиенты блока.
- `assets/hero-video.mp4` в макете не используется (hero — фото bg-1) — не обрабатывалось.
- Пересборка после замены снимка: `photos.json` / `photo_overrides.json` → `python photo_catalog.py` → `photo_tone.py` → `build_photos.py` →
  `node images.mjs`. Для нового снимка без рендера Figma тон брать кривой соседнего фото той же поверхности.
- Инструменты этапа: `figma_images.py`, `match_photos.py`, `photo_tone.py`, `photo_catalog.py`, `photo_sheet.py`, `build_photos.py`, `images.mjs`,
  `logo.py`, `og.py`; поставлен `potracer` (pip). Мастера — `tools/.cache/masters/` (не в `site/`).
- Грабли figma-mcp-express: `get_image_by_hash` в этом файле не работает («Image dimensions not available»); `save_screenshots` игнорирует `scale`
  и режет узел по окну родителя; скрытый или прозрачный узел даёт пустой PNG 149 байт; поверх существующего файла не пишет.
