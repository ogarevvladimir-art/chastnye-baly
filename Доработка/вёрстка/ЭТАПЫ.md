# Этапы вёрстки

Каждый этап — отдельная сессия, этапы идут строго по очереди. Перед стартом агент читает `ОБЩЕЕ.md`, этот файл,
конец `ЖУРНАЛ.md` и `../адаптив/ПЕРЕДАЧА.md`.

Внутри этапа блоки верстаются по одному, сразу на всех трёх ширинах. Порядок по каждому блоку:
1. рендер Figma;
2. HTML;
3. CSS 390 → 834 → 1440;
4. поведение;
5. сверка (пары «Figma | сайт» и видео);
6. «да» пользователя;
7. запись в ЖУРНАЛ.

Figma — только чтение, через figma-mcp-express. Если плагин не подключён, попросить пользователя его запустить.

Запуск этапа в новой сессии:
> Вёрстка «Частных балов», этап N. План — `Доработка/вёрстка/` (ОБЩЕЕ, ЭТАПЫ, ЖУРНАЛ), правила адаптива —
> `Доработка/адаптив/ПЕРЕДАЧА.md`. Проект — `site/`.

## Этап 0 — Основа и инструменты — закрыт 2026-10-02 (итог — ЖУРНАЛ)

Цель: дальше каждый блок решает только свою композицию, а не шрифты, масштаб и сверку.

1. **Инвентаризация Figma.**
   - Секции `191:626` по порядку: ID, высоты, фон, якорь.
   - Переменные и стили: цвета, текстовые стили `v2/…`, `v2/M/…`, `v2/T/…` с vw-коэффициентами из описаний.
   - Таблица «блок → покой 1440 / 834 / 390 → состояния → заметки» — в ЖУРНАЛ.
2. **Текст.** Выгрузить весь текст `191:626` по блокам в `ТЕКСТ.md` (с курсивными фрагментами и разрывами строк),
   сверить с кадрами 390 и 834. Расхождения между ширинами — флаг.
3. **Шрифты.** Скачать Unbounded (variable, OFL), взять Old Standard TT из `Шрифты/`, сабсет латиница + кириллица + типографские знаки
   → `site/fonts/*.woff2`. Проверить кернинг и трекинг −3 % / −5 % против рендера Figma.
4. **Токены и роли.**
   - `tokens.css`: цвета, поля, брейкпойнты, кегли через `clamp()` по формулам ПЕРЕДАЧА 1.
   - `base.css`: сброс, `.t-…` роли.
5. **Каркас `index.html`.** Все секции пустыми `<section id>` в порядке страницы с фоном и минимальной высотой. Шапка — заглушка.
6. **Инструменты** в `tools/`:
   - `shots.py` — Playwright, ширины из ОБЩЕЕ, chromium и webkit, полная страница и отдельный блок по селектору;
   - `pair.py` — склейка «Figma | сайт»;
   - `video.py` — запись скролла;
   - `images.mjs` — sharp, болванка для этапа 1;
   - `fonts.py` — сабсет.

   `package.json` и `node_modules` — только в `tools/`.
7. **Тестовая страница ролей** `tools/roles.html` (не в `site/`): все роли на 360 / 390 / 600 / 834 / 1024 / 1440 / 1920,
   рядом — доска системы Figma. Утвердить с пользователем.

**Развилка (AskUserQuestion):** что происходит шире 1440. Варианты: продолжать vw, как ore; композиция 1440 по центру с полями;
vw до 1920, дальше потолок.

**Готово, когда:** пользователь утвердил страницу ролей; шрифты, токены, каркас и инструменты есть; `ТЕКСТ.md` и таблица кадров в ЖУРНАЛ.

## Этап 1 — Медиа: фото и логотип — закрыт 2026-10-02 (итог — ЖУРНАЛ)

1. **Каталог фото.** Для каждой картинки макета (десктоп и адаптив):
   - блок и роль;
   - рамка на 390 / 834 / 1440;
   - исходник в `assets/`, найденный по совпадению кадра (скрипт сравнения миниатюр);
   - кроп или `object-position`;
   - нужен ли отдельный кроп для телефона.

   Таблица — в ЖУРНАЛ, а слабые исходники сверить со списком ПЕРЕДАЧА 6.
2. **`images.mjs`.** Из исходника и кропа — AVIF / WebP / JPEG под 1× / 2× / 3× каждой рамки, без апскейла выше исходника.
   Цель — фото ≤ 200 КБ (AVIF) на телефоне. Тон фото («фото с цветом») сверить с рендером Figma: если в Figma на фото
   стоит фильтр или наложение, перенести в CSS или запечь в файл — по согласованию.
3. **Чужие логотипы в кропах** (Форматы «корпоративные», 03 «Группа», 04) — отдельные кропы без задника. Если такого кропа
   не получается, показать пользователю варианты.
4. **Логотип.**
   - Спросить у пользователя SVG.
   - Если SVG нет — векторизовать растровый (potrace или вручную), показать рядом с оригиналом при 2×.
   - Сделать светлый и тёмный варианты.
   - Сделать favicon (SVG, ICO 32, apple-touch 180) и `og.jpg` 1200 × 630.

**Готово, когда:** все фото страницы лежат в `site/img/`, пользователь посмотрел контактный лист кропов, логотип утверждён.

## Этап 6 — Форма, юридическое, служебные страницы

**Вопросы пользователю (AskUserQuestion):**
- куда идут заявки: Telegram, почта или оба;
- тексты «отправлено» и ошибок — если заказчик ещё не дал, оставить заглушки;
- аналитика: Метрика или нет.

**Работа:**
1. **`send.php`.**
   - Валидация на сервере.
   - Защита от спама: honeypot, минимальное время заполнения, лимит по IP.
   - Отправка в выбранный канал. Токены и адреса — в `_private/config.php` под `Require all denied`.
   - JSON-ответ.
   - Фронт отправляет через `fetch`, без JS работает обычный POST с редиректом на `?sent=1`.
   - Убрать из `form.js` имитацию отправки и сбоя (`?form=error`), заглушки `data-stub` заменить текстами заказчика.
2. **152-ФЗ.** Согласие на обработку персональных данных у кнопки отправки (текст и ссылка — на согласование), `privacy.html`
   в стиле сайта. Текст политики из `Прототип/privacy.html` показать пользователю: годится ли.
3. **Аналитика.** Если «да» — Метрика с целями «открыл форму» и «отправил заявку», без Вебвизора. Плюс плашка cookie в языке сайта.
4. **`404.html`** в стиле сайта (H2 и ссылка на главную).
5. **Проверка `send.php` локально:** `php -S`. Если PHP не установлен — portable-сборка в `tools/`.

## Этап 7 — Качество и деплой

1. **Доступность.** Клавиатура по всей странице, `:focus-visible`, порядок фокуса в меню и форме, `aria` у переключателей и
   карусели, reduced-motion, масштаб текста 200 %.
2. **Производительность.** Lighthouse mobile и desktop (`npx lighthouse` из `tools/`) по бюджету ОБЩЕЕ. Preload hero и шрифтов,
   lazy ниже первого экрана, нет лишних перерисовок при скролле.
3. **Браузеры.** Playwright chromium + webkit на всех ширинах из ОБЩЕЕ. Горизонтального скролла нет нигде.
   Проверка на телефоне и старых iOS убрана из плана (решение пользователя 2026-10-04); пользователь смотрит в Chrome (десктоп и режим устройства).
4. **SEO и превью.**
   - `title`, `description`, canonical, OG / Twitter, `og.jpg`;
   - schema.org `Organization` / `LocalBusiness`;
   - `robots.txt`, `sitemap.xml`.
   - Спросить домен, реальные телефон и почту. Без домена OG-карточка не соберётся (адреса должны быть абсолютными).
5. **`.htaccess`.** Редирект на https и без www (или наоборот — спросить). Кэш: `immutable` для `fonts/` и `img/`,
   короткий для `html`. Сжатие gzip / brotli, `ErrorDocument 404`, `Options -Indexes`.
   Версии в именах CSS и JS (`main.css?v=…` или хэш).
6. **Чистота `site/`.** Нет исходников, черновиков, `.DS_Store`, неиспользуемых фото. Скрипт `tools/check_site.py`:
   битые ссылки и ссылки на несуществующие файлы, вес страницы, список файлов.
7. **`ДЕПЛОЙ.md`** — как залить на Beget / Timeweb: куда класть `site/` (обычно `public_html`), SSL, где поменять токены формы,
   как проверить отправку. Архив `site.zip` — по просьбе.

**Готово, когда:** пользователь проверил сайт в Chrome (десктоп и режим устройства), бюджет выполнен, `ДЕПЛОЙ.md` готов. В ЖУРНАЛ — «Вёрстка закрыта».
