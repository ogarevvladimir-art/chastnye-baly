## Wow-эффекты на телефоне

Наведения на телефоне нет. Каждое десктопное состояние получает замену одного из трёх типов:

1. **От скролла** (главный wow и главный язык ore на телефоне): закрепление, проезд гиганта,
   сжатие разрядки, раскрытие фото от оси, активная строка в центре экрана, барабан слова.
   В Figma это **раскадровка из трёх кадров** (0 % / 50 % / 100 % прохода) плюс заметка для разработки:
   где эффект стартует и заканчивается (в % высоты экрана), что меняется (только transform, opacity,
   clip-path), кривая, запасной вариант при `prefers-reduced-motion`.
   **Поправка этапа 0:** у ore на телефоне эффекты — **анимации входа по времени** (сборка гиганта из
   растянутых букв ≈ 1,3 с, проявление антиквы ≈ 0,8 с), закреплений и скраба нет. Для таких эффектов
   раскадровка — 0 / 50 / 100 % **времени**, в заметке: «старт — верх элемента на 90 % экрана, один раз,
   длительность, кривая expo-out». Закрепление и скраб — наши ходы, не больше двух на страницу.
2. **Тап** — раскрытие, переключение ролей. Прототип Figma: ON_CLICK → Smart Animate 0.35 EASE_OUT.
3. **Свайп** — карусели, занавес. Прототип Figma: горизонтальный скролл кадра или ON_DRAG → Smart Animate.

Правила для разработки, которые пишутся в заметки: единицы `svh`/`dvh` (адресная строка меняет высоту),
закрепление не длиннее 150svh, без перехвата скролла, зоны нажатия от 44 × 44, при reduced-motion —
статичный кадр покоя.

## Порядок работы по блоку

Как в «ore-заголовках», но с поправками, которые пользователь дал на прошлых этапах:

1. Отрендерить десктопный покой и состояния (`save_screenshots` пишет только в `VS CODE/.figma-shots/`,
   путь относительный; существующий файл не перезаписывается — новое имя).
2. Предложение пользователю: **Сейчас → Что не работает на телефоне** (нумерованно, с цифрами:
   кегли, ширины) **→ A / B → D общие правки → рекомендация → где лягут кадры**. Дождаться выбора.
3. **По умолчанию рекомендовать ближайший перенос десктопа** — тот же приём, разложенный под телефон.
   Смелую перестройку давать альтернативой. Удачные части десктопа без просьбы не перестраивать.
4. **Сначала собрать один кадр покоя 390 и показать.** Состояния, раскадровку и прототип — после «да».

## Грабли инструмента (собраны на прошлых этапах)

- `create_text` со стилем требует явных fontFamily/fontStyle, а явный шрифт отвязывает стиль —
  после создания повторить `set_text textStyleId`. Стиль Body/Text сам даёт капс: ручной UPPER отвязывает стиль.
- `create_text` не принимает layoutSizing — размер через `resize_nodes`; после `resize_nodes` по тексту
  снова `set_text textAutoResize HEIGHT`. `resize_nodes` всегда с обеими сторонами (height 0 обнуляет).
- Фреймы с фиксированной высотой в auto-layout схлопываются — `layoutSizingVertical: FIXED`.
  Новые фреймы приходят с белой заливкой — чистить `set_fills` с пустым paints.
- Дети с `layoutPositioning: ABSOLUTE` игнорируют auto-layout родителя — переводить в AUTO отдельно.
- `set_reactions`: у MOUSE_ENTER обязательно `delay: 0`; тайминги триггеров — в мс.
- Клон кадра с потомками: ID сдвигаются на константу.
- Перезапись IMAGE у CROP-кадров сбрасывает кадрирование — фото перекадрировать клоном в обрезающей рамке.
- `rename_node` переименовывает только первый из nodeIds — для нескольких нужен `map`.
  То же у `set_text` (например, `textAutoResize`). Форма `map`: `{type:"map", over:[…], as:"id",
  do:{type, nodeIds:["$id"], params}}` — без обёртки `params` вокруг `over/do`.
- `create_text` возвращает ширину до применения `textCase: UPPER` — ширину капса мерить после
  (`textAutoResize: WIDTH_AND_HEIGHT` → `get_nodes_info`).
- `move_nodes` и `create_*` с `parentId` работают в координатах родителя.
- Кадры без авто-лейаута: при создании `create_frame` белую заливку сразу задавать через `fillColor`,
  потом привязывать к переменной `set_fills {variableId}`.
- Масок в batch нет; окно в буквах — только boolean.
- Фильтры изображения (exposure, contrast, saturation) отдельной операцией не ставятся, но проходят через `set_fills paints: [{type: IMAGE,
  imageHash, scaleMode, filters: {…}}]` (этап 4, тёмный логотип-заглушка).
- `get_prototype` по странице подвисает (120 с) — реакции проверять `get_reactions` по узлам, старты — ответом `set_prototype_start`.
- Batch иногда отвечает «rpc transport failed», хотя операции применились: сначала прочитать узел, не повторять batch вслепую.
